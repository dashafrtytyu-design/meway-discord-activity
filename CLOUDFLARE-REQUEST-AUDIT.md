# MEWAY: аудит запросов и экономии Cloudflare (14.10.2026)

## Проверенное в исходном коде
- Вход через Discord: **1 клиентский POST `/api/auth/discord`** на одну успешную авторизацию. В ответ включены роли, прогресс, версии, Placement и каталог; отдельные запросы за manifest/progress/access при этом не нужны. Сервер дополнительно обращается к Discord OAuth/API; это не Worker-запросы от браузера.
- D1 при обычной авторизации: минимум 3 прямых чтения (`progress`, `placement_results`, `ui_config`); для не-администратора ещё чтение `course_access`. `meway_meta` читается при отсутствии warm-cache. `listMissions` и три `listContent` могут читать D1 и tombstone-таблицы при отсутствии серверного кеша; точное число зависит от холодного старта, наличия кеша и базы. Первый вход нового ученика дополнительно выполняет `INSERT OR IGNORE` в `progress` и, при наличии KV, публикацию сигнала. `ensureDb` на холодном isolate выполняет DDL через DB.exec: это дополнительная нагрузка, которую нельзя игнорировать в реальном замере.
- Открытие уже загруженного раздела: **0 Worker-запросов** при наличии данных в session Map; **0 Worker-запросов** при наличии IndexedDB и отсутствии расхождения версии. При изменении версии/ревизии возможен **1 запрос** `/api/content` либо `/api/sync` при открытии раздела. Отдельного polling нет.
- Обычное сохранение материала: **1 запрос браузер → Worker** (POST/PUT). На стороне Worker: `SELECT` текущей записи (1), `INSERT` или `batch(INSERT history, UPDATE)` (1–2 записи), `SELECT` для проверки содержимого (1), `DELETE` tombstone (1 запись), `SELECT` ревизий при cache miss (0–1), `INSERT OR REPLACE` ревизии (1 запись). Это около **2–3 D1 чтений + 2–4 D1 записей/операций**, без учёта DDL и чтений при проверке админских прав. Проверка JSON, включая Data URL, делается **внутри того же Worker-запроса**. На нормальном успешном пути дополнительного HTTP verify нет.
- При ошибке/потере ответа клиент может вызвать `/api/admin/content/:id/verify` и повторить сохранение (до 3 попыток). Это дополнительные запросы **только при сбоях**; они нужны, чтобы не создавать дубликаты и выяснить результат неоднозначной записи.
- Локальный фокус-таймер использует `setInterval` каждую секунду, но он обновляет только часы в интерфейсе и **не вызывает Cloudflare**.

## Важные ограничения
- Подсчёт выше — **статический аудит исходников**, а не измерение Cloudflare Analytics. Реальные числа могут отличаться из-за cold starts, кеша, авторизации и прав доступа. Для точных значений используйте Cloudflare Workers Observability + D1 metrics на тестовом проекте, с отдельными измерениями первого и повторного входа.
- Версионный заголовок `If-Unmodified-Since-MEWAY` сервером поддерживается, но в текущем клиентском сохранении `App.tsx` его передача **не подтверждена**. Поэтому нельзя утверждать, что защита от параллельного редактирования полностью включена. Не следует вводить обязательный заголовок на сервере до обновления всех клиентов: это сломает публикацию.
- Нет подтверждения реальной D1 и безопасного восстановления всех типов материалов. Никакие тесты не заменяют проверку резервного копирования и восстановления на отдельной тестовой базе.

## Как измерить без лишнего фонового трафика
1. Сделайте экспорт/снимок production D1 и работайте на отдельном тестовом окружении с копией данных.
2. Откройте Network браузера, включите Preserve log и фильтр `/api/`. Войдите один раз, запишите запросы.
3. Откройте раздел с уже прогретым кешем, проверьте, что не появился новый `/api/content`/`/api/sync`.
4. Сохраните одну тестовую карточку, проверьте один POST/PUT, код 2xx, совпадение всех полей в ответе.
5. В D1 Console **тестовой базы** выполните только SELECT по id и проверьте полный JSON и изображение. После перезапуска и очистки кеша повторите проверку.
6. Сравните D1 reads/writes в Cloudflare Analytics до и после этих действий; учитывайте `ensureDb` на холодном Worker.

## Запреты для будущих изменений
Никаких фоновых проверок раз в N секунд, автосинхронизации при смене вкладки, повторных GET после успешного сохранения с серверной проверкой, загрузки всего каталога при каждом рендере. Нельзя экономить на проверке admin, версии, идемпотентности, истории и записи XP.
