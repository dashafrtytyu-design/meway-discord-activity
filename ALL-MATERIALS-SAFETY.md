# MEWAY: защита всех материалов — 2026-10-14

## Изменено
- Удалён датированный фильтр, скрывавший ранее сохранённые игры в D1. Это исправление отображения, не миграция данных.
- Импорт резервной копии переведён в режим `restore_missing_only`: восстанавливает только отсутствующие записи материалов и миссий по исходным ID; существующие записи, настройки, прогресс, tombstones и права доступа не перезаписывает. Возвращает `restored` и `skipped`. Старые экспортные JSON-файлы остаются читаемыми.
- После записи материала сервер сверяет весь JSON, прочитанный обратно из D1, с отправленным JSON, включая Data URL изображения. При несовпадении возвращает ошибку.
- Редактирование отсутствующей записи не создаёт её заново молча.
- Для редактирования и удаления миссий добавлена история `mission_history`; изменение использует сравнение версии строки.
- Добавлены регрессионные тесты.

## Важные ограничения
- Фотографии по-прежнему хранятся Data URL внутри D1 JSON. При больших объёмах это дорого по размеру: base64 увеличивает данные примерно на треть; каждая правка с историей копирует весь JSON. Длительная стратегия: Cloudflare R2 для изображений и неизменяемые ключи/контрольные суммы в D1. R2 требует отдельной проверки лимитов, включения и согласия владельца; в этом обновлении R2 НЕ подключён.
- В браузере экспорт всего набора может превысить лимиты ответа Worker или памяти, особенно при тысячах фото. Для полноценного резервирования нужно делать D1 export через Cloudflare, проверять полученный файл, хранить отдельную копию вне Cloudflare. Простой JSON-экспорт приложения не заменяет D1 backup.
- Миссии и карточки ещё не имеют обязательного токена версии на каждом запросе клиента: при конкурентных вкладках остаются сценарии перезаписи. Сервер сравнивает актуальную строку в момент записи, но для полной защиты нужно передавать версию при каждом редактировании и запрещать сохранение без неё.
- История версии содержимого D1 не является независимой резервной копией: при потере базы пропадёт и история.
- Автотесты по исходникам НЕ доказывают работоспособность на настоящем Cloudflare. Не загружайте массово до реальных проверок.

## Проверка Cloudflare без изменения данных
1. В Cloudflare → Workers & Pages → MEWAY → Bindings убедитесь, что `DB` привязан к ожидаемой D1 `meway-content` и сравните её `database_id` с предыдущим деплоем. Не создавайте новую базу.
2. В D1 → Console выполните только SELECT: `SELECT section, COUNT(*) AS n FROM content GROUP BY section;` и `SELECT COUNT(*) AS n FROM missions;`.
3. Сделайте Cloudflare D1 backup/export до любого деплоя; сохраните его вне Cloudflare и проверьте, что файл непустой.
4. На отдельной тестовой базе/окружении: создайте материал с изображением, проверьте `SELECT id,length(data),instr(data,'data:image/') FROM content WHERE id=<ID>;` (для WebP/PNG Data URL); после повторного входа, очистки кеша и обновления приложения проверьте тот же ID, содержимое и картинку у ученика.
5. Проверьте редактирование текста вместе с заменой фото, удаление фото без удаления текста, две вкладки с одновременным редактированием и восстановление из отдельного экспорта.
6. Не запускайте импорт резервной копии в рабочей базе до проверки на тестовой базе.
