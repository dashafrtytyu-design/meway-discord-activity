MEWAY V7.19.7 — REQUEST / DELETION HARDENING

- Student navigation still contains no Admin entry. Admin UI renders only when Discord server-side auth returns role=admin.
- Student leaderboard remains available to authenticated students; Discord IDs are not included in leaderboard responses.
- Custom/admin-created content and missions are now physically DELETEd from D1 without creating a deletion tombstone.
- Built-in curriculum is compiled into the Worker bundle. A runtime admin action cannot physically remove bytes from a deployed Worker bundle. For built-in items only, a small D1 deletion marker remains necessary so deleted built-in content cannot reappear after Worker restart/redeploy. This marker is metadata, not the deleted lesson payload.
- Existing persistent cache/delta sync remains in place to minimize repeated content downloads.
- UI remains responsive via existing desktop/tablet/mobile CSS breakpoints.

IMPORTANT ARCHITECTURE NOTE
It is not technically possible to guarantee both (a) runtime deletion of compiled-in content with zero persistent deletion state and (b) no redeploy. To physically erase built-in content, it must be removed from contentSeed/source and the Worker redeployed, or all curriculum must be migrated to D1 as the source of truth. Migrating all curriculum to D1 would increase database dependence/reads, which conflicts with the current cloud-minimization goal.
