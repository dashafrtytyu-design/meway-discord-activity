# MEWAY — исправление определения администратора

Причина риска: клиент имел отдельный захардкоженный Discord ID администратора, а сервер определял права по env.ADMIN_DISCORD_ID. Кешированная роль могла оставаться устаревшей.

Исправлено: роль при OAuth берётся из серверного ответа; существующий GET /api/progress-signal теперь передаёт роль, а клиент обновляет кеш и интерфейс из неё. Дополнительных HTTP-запросов нет. API /api/admin/* по-прежнему проверяет права на сервере.

Проверка после публикации:
1. В Cloudflare Worker проверь переменную ADMIN_DISCORD_ID: она должна совпадать с Discord User ID владельца (не ID сервера, приложения или бота).
2. Убедись, что Discord Activity обращается к тому же Worker, который ты обновила.
3. Перезапусти Discord Activity. Вкладка «Админ» должна появиться, а уровни стать доступны администратору.
4. Если не появится: в DevTools Network открой ответ POST /api/auth/discord или GET /api/progress-signal и проверь поле role. Не пересылай accessToken. Если role=student, исправляй ADMIN_DISCORD_ID на сервере; не выдавай права только на клиенте.

Рабочая D1 не менялась. Реальная Discord/Cloudflare проверка не выполнялась.
