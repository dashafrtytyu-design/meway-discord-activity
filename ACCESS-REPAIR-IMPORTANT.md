# MEWAY — исправление выдачи доступов

Исправлено: запись доступа в D1 больше не зависит от успешной записи сигнала KV. Отсутствие ACCESS_SIGNALS больше не приводит к 503 на /api/progress-signal. UI выдаёт понятную ошибку, если вместо JSON пришёл HTML. Выдача нескольких уровней A1–C2 одним запросом сохранена.

## Обязательные настройки Cloudflare

1. Опубликуйте **Worker**, а не только статические файлы Vite/Pages. В `wrangler.jsonc` уже указано `main: worker.ts`, `run_worker_first: ["/api/*"]`.
2. В Cloudflare Workers & Pages → ваш Worker → Settings → Bindings проверьте **D1 binding**: имя переменной `DB`, база `meway-content` (та самая база, где хранится прогресс). Если деплой выполняется через Wrangler, укажите реальный `database_id` из Cloudflare в `wrangler.jsonc` (не выдумывайте ID).
3. Создайте KV namespace и привяжите к Worker под точным именем `ACCESS_SIGNALS`. Если деплой выполняется через Wrangler, укажите реальный KV namespace id в `wrangler.jsonc`. Без KV выдача в D1 теперь работает, но синхронизация доступов между устройствами будет отложена до повторной авторизации.
4. Убедитесь, что `DISCORD_CLIENT_SECRET` задан как Worker Secret, `ADMIN_DISCORD_ID` совпадает с администратором.
5. Проверьте `https://ВАШ-ДОМЕН/api/health`. Должен приходить JSON, а не HTML. Если HTML — API route не направлен в Worker. Если `ready:false` — проверьте секреты и D1.
6. Для ошибки HTTP 500 откройте Cloudflare Worker → Logs и проверьте конкретную серверную ошибку. Только лог Worker может точно определить, почему упала D1 операция.

ВНИМАНИЕ: без реальных Cloudflare привязок код не сможет создать их сам. Не заменяйте существующую D1 на новую пустую базу — иначе пропадёт доступ к ранее сохранённым данным.
