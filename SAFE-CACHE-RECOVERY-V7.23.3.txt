MEWAY V7.23.3 — SAFE CACHE RECOVERY

Purpose
- Clearing browser/site cache must not reset a student's server-backed MEWAY state.
- D1 remains the source of truth; IndexedDB/localStorage are only fast local working copies.

Recovery flow
1. Student reopens MEWAY and authenticates with the same Discord account.
2. The existing /api/auth/discord request (already required) returns access levels, revisions,
   saved progress, Placement completion state and the last Placement result.
3. No second recovery API request is made.
4. MEWAY writes an encrypted per-user recovery snapshot into IndexedDB and rebuilds missing
   local progress/Placement working copies.
5. Curriculum caches refill normally from versioned/static content only when missing or stale.
6. MEWAY returns to the normal Cloud Saver cache/delta-sync mode.

Recovered server-backed state
- Discord identity / app role
- granted CEFR/course access
- XP and saved progress payload
- completed mission/content state contained in progress
- mistakes/stats/streak/activity state contained in progress
- Placement completion + latest Placement result
- content revisions needed to validate/refill local curriculum cache

Security
- Recovery is keyed by authenticated Discord user ID.
- D1 is never copied to the browser as a database.
- Other students' records and admin database records are never included.
- Admin authorization remains server-side via requireAdmin/ADMIN_DISCORD_ID.
- Local recovery snapshot uses the existing AES-GCM IndexedDB cache wrapper.

Cloud impact
- 0 additional recovery HTTP requests compared with normal Discord Activity startup.
- 0 additional D1 reads for recovery beyond rows already read by auth; Placement query now returns
  its existing data column in the same point lookup instead of only updated_at.
