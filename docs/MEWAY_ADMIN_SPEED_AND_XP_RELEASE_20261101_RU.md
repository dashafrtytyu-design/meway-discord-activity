# MEWAY — быстрое управление контентом, список учеников и контраст поздравления

Дата: 1 ноября 2026 г. Основа: ранее проверенная версия `MEWAY_Cloudflare_publication_MASTER_ZONE_fix_20261101.zip` (ещё НЕ опубликованная).

## Что рассказала администратор
- Новые миссии и игры появляются в списке не сразу; после задержки обнаруживаются, затем их можно удалить.
- Открытие админки, создание и редактирование материалов сопровождаются задержками.
- На синей плашке нового уровня поздравление и подсказка выглядят серыми; требуется белый.
- В карточках учеников нужен актуальный XP из приложения, ручная выдача уровней A1–C2, без постоянного опроса.
- Отдельный Python-бот будет только для статуса онлайн, но это отдельный, более поздний этап.

## Исправления в `worker.ts`, `src/App.tsx`, `src/App.css`
1. Административные списки миссий и контента запрашиваются в `compact=1` и отдаются без тяжёлых `payload` (изображений, слов, вопросов) и без полных задач миссий. Количество заданий миссии остаётся в `taskCount`.
2. Полная игра, миссия или другой материал загружается отдельным GET **только при нажатии «Изменить»**. Изменения сохраняются существующими PUT/POST, API экспорта и кнопками удаления.
3. В админке одновременно отображаются не более 40 карточек раздела; есть поиск по названию, категории, теме, уровню и ID, кнопка «Показать ещё 40». Новые элементы отображаются сверху.
4. Редактор слов сохраняет локальное обнаружение повторяющихся слов: полные словарные коллекции загружаются отдельно **только при открытии редактора слов**, а не при входе в админку.
5. `.levelUpToast` и его подписи окрашены в чистый белый во всех режимах оформления, улучшена читаемость малой подписи.
6. Список учеников при открытии и по кнопке «Обновить учеников» получает свежую страницу D1 без 15-секундного серверного кэша и показывает момент последнего обновления. Без бесконечного polling. Подробности ученика — только при открытии карточки.
7. На странице учеников явно разделены ручной доступ A1–C2 (D1) и отображаемый XP (из `progress.data` в D1). Логика выдачи ролей Discord по XP остаётся прежней.

## Что НЕ менялось
- `wrangler.jsonc`, binding действующей D1, секреты, `DISCORD_BOT_TOKEN`, ID Discord-бота, ID Discord-сервера.
- XP-награды, `syncDiscordLevelRole`, порог MASTER ZONE 10000 XP, алгоритмы начисления, правила Placement Test, пять вариантов теста, доступ к курсам и его существующая серверная реализация.
- Существующие миссии, слова, игры, квизы, черновики, таблицы D1 и учебные материалы.
- Worker онлайн **не публиковался автоматически**; никто не удалял учеников или контент.

## Проверки
- 115 тестов Node.js: успешно. В том числе созданная тестовая игра появляется через два экземпляра Worker, полная редакторская загрузка сохраняет картинку, компактный список не несёт картинки, проверка MASTER ZONE не изменяет роли.
- `worker.ts` и `src/App.tsx` проверены парсером TypeScript, ошибок синтаксиса нет.
- `npm run build` в текущей среде НЕ выполнен до конца: отсутствуют установленные определения типов `vite/client` и `@types/node`. В Codespaces нужно выполнить `npm ci`, затем `npm run test:all`, `npm run build`.
- Живая D1, опубликованный Worker, реальный Discord API и реальные задержки браузера не тестировались. Поэтому ускорение обосновано сокращением работы, но не измерено на продакшене и не гарантирует нулевых задержек.

## Как безопасно обновить именно существующий MEWAY
1. Перед любыми действиями **Админ → Резервные копии MEWAY → «Вся база»**. Дополнительно SQL-снимок настоящей Cloudflare D1 (из существующего Codespace, где настроен Wrangler):

   `npx wrangler d1 export meway-content --remote --output=meway-backup-before-admin-speed.sql`

   Хранить вне репозитория. Не импортировать старый JSON поверх более нового прогресса.
2. Убедиться, что рабочий GitHub-репозиторий соответствует исходному архиву MEWAY 7.31.26. Если за это время были новые правки в GitHub, сначала сравнить / объединить изменения — не заменять его полностью старым ZIP.
3. Скопировать только `worker.ts`, `src/App.tsx`, `src/App.css`, три теста (`tests/worker-content-live-contract.test.mjs`, `tests/admin-performance-contract.test.mjs`) из пакета изменённых файлов. `worker.ts` и `src/App.tsx` уже содержат исправления предыдущего патча публикации и MASTER ZONE.
4. В Codespaces выполнить `npm ci`, `npm run test:all`, `npm run build`. Если хотя бы один шаг провалился — **не публиковать**.
5. После успешной сборки и резервного копирования — `npx wrangler deploy`. Убедиться, что обновляется **тот же Worker** и подключена **та же D1**, без создания новой базы и без SQL-очисток.
6. Проверить Админ → Игры, Миссии, Слова и Ученики. Создать маленькую тестовую игру, опубликовать, найти её через поиск, проверить появление в ученическом разделе, отредактировать, убедиться, что изменение появилось. Проверить то же для миссии.
7. Проверить вручную актуальность XP ученика после кнопки «Обновить учеников» и разрешения MASTER ZONE в «Автоматизация → Проверить выдачу MASTER ZONE». Диагностика проверяет права и токен, но не присваивает роль тестовому ученику.
8. Не запускать Python-бота с начислением XP/выдачей ролей параллельно с Cloudflare. Облегчённый онлайн-бот будем рассматривать отдельно после проверки приложения.

## Важно
Лёгкий список уменьшает размер сетевых ответов и число отрисовываемых карточек, но сервер при первом запросе всё ещё собирает каталог из D1 и встроенных материалов. При очень больших коллекциях с фотографиями в будущем может потребоваться постраничная SQL-выборка или перенос изображений из JSON в отдельное хранилище. Это отдельная архитектурная работа — здесь структуру данных не меняли ради сохранности.
